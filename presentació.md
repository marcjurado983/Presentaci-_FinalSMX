## 🟢 PART 4 — Metodologia de treball

### 📌 Kanban

```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│   PENDENT   │──▶│   EN CURS   │──▶│ EN REVISIÓ  │──▶│     FET     │
│─────────────│   │─────────────│   │─────────────│   │─────────────│
│ · Tasca A   │   │ · Tasca B   │   │ · Tasca C   │   │ · Tasca D ✓ │
│ · Tasca E   │   │             │   │             │   │ · Tasca F ✓ │
└─────────────┘   └─────────────┘   └─────────────┘   └─────────────┘
```

> 💡 **Cas real — Projecte 06 (Nexus):** Una tasca de configuració de serveis va passar de *"pendent"* a *"en revisió"* dues vegades per problemes de connectivitat. Es va reorganitzar el tauler per prioritzar la resolució del problema tècnic.

### 🚨 Gestió d'imprevistos — Cas real

> **Problema:** Una tasca de configuració de servei de xarxa va trigar el doble del previst per un **conflicte de ports**.

```
Pas 1 → Identificar el problema al log del sistema
           ↓
Pas 2 → Reorganitzar tasques al tauler Kanban
           ↓
Pas 3 → Documentar la solució al repositori GitHub
           ↓
Resultat → Problema resolt + coneixement reutilitzable ✅
```
